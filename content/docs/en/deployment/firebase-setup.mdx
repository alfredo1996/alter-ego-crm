## Create a Firebase Project

1. Go to the [Firebase Console](https://console.firebase.google.com)
2. Enable **Firestore Database** in production mode
3. Enable **Authentication** with the Email/Password provider
4. Enable **Storage** (invoice files)

## Security Rules

Build and deploy the rules, which `pnpm rules:build` assembles from `firestore/base.rules`, `firestore/crm.rules` and the modules' rules:

```bash
pnpm setup:owner YOUR_UID   # once, before the first deploy (see below)
pnpm rules:build
firebase deploy --only firestore:rules,firestore:indexes,storage --project YOUR_PROJECT_ID
```

Sign-up is closed. Before you deploy, run `pnpm setup:owner <uid>` with your user's uid: it writes the uid into `firestore/base.rules`, `storage.rules` and `apps/web/src/lib/owner-uid.ts` and rebuilds `firestore.rules`. A copy without it lets nobody write. Commit the four changed files to the branch App Hosting builds, in your own copy of the repository, before the rollout: the server reads `owner-uid.ts` from that build.

## Environment Variables

Set the `NEXT_PUBLIC_FIREBASE_*` variables (see the Getting Started page) and `NEXT_PUBLIC_BACKEND=firebase`. Optionally list the plugins to run in `NEXT_PUBLIC_PLUGINS` (for example `consulting,accounting,rent`, which is also what unset means; add `finance` for Personal Finance, or list only `finance` to run it alone).

## Local Emulator

To run against a local emulator that keeps its data, see `docs/SELF-HOSTING.md` in the repository: `pnpm local:start`, `pnpm local:seed`, then `pnpm dev:emulator`.

See `docs/DEPLOYMENT.md` in the repository for the full App Hosting steps.
