## Test Unitari (Vitest)

**354+ test unitari** coprono utility, logica di business e l'adapter del backend mock.

```bash
# Modalità watch
pnpm test

# Esecuzione singola
pnpm test --run

# Con copertura
pnpm test --run --coverage
```

### File di Test

I test risiedono nelle directory `__tests__/` accanto al codice che testano:

```
src/lib/__tests__/
  ├── dates.test.ts
  ├── export.test.ts
  ├── merchants.test.ts
  ├── net-worth.test.ts
  ├── amortization.test.ts
  └── ...
src/lib/backend/__tests__/
  ├── adapter-contract.ts  # Test contrattuali condivisi
  ├── mock.test.ts
  ├── mock.adapter.test.ts
  └── firebase.adapter.test.ts
```

### Backend Mock nei Test

Resetta sempre lo stato tra i test:

```typescript
import { getBackend } from "@/lib/backend"

beforeEach(() => {
  const backend = getBackend()
  ;(backend as any).__resetMockState()
})
```

### Test Contrattuali

La suite di test contrattuali dell'adapter (`adapter-contract.ts`) definisce 97 test condivisi che qualsiasi adapter backend deve superare. Vengono eseguiti contro l'adapter mock a ogni `pnpm test`, e contro Firebase sull'emulatore con `pnpm test:firebase:docker`.

## Test E2E (Playwright)

I test E2E coprono i flussi utente critici usando il backend mock, contro una build di produzione. **30 file spec**, uno per area.

```bash
pnpm test:e2e
```

Un'installazione senza Fatturazione e Soluzioni è una build a sé: `pnpm test:e2e:modules` esegue `modules.spec.ts` contro di essa.

### Spec dei Test

```
e2e/
  ├── auth.spec.ts, sign-out.spec.ts, oauth-consent.spec.ts   # Accesso, uscita, pagina di consenso del connettore
  ├── navigation.spec.ts, redirects.spec.ts, settings.spec.ts
  ├── crm.spec.ts, collaborators.spec.ts, solutions.spec.ts    # Pipeline, clienti, contratti, collaboratori, soluzioni
  ├── billing.spec.ts, invoice-files.spec.ts                   # Fatture e relativi file
  ├── cash-book*.spec.ts, month-end*.spec.ts, rent.spec.ts     # Prima nota e Affitti
  ├── plan-*.spec.ts, hours.spec.ts                            # Il Piano, runway e trimestri
  └── mobile.spec.ts, loading-states.spec.ts, modules.spec.ts  # Correzioni telefono, stati di caricamento, un modulo escluso
```

### Pattern

- I test vengono eseguiti contro il backend mock per velocità e isolamento
- Usano selettori `aria-label` e basati su ruolo per l'accessibilità
- Le interazioni solo desktop (menu hover, dropdown) vengono testate nel viewport desktop
